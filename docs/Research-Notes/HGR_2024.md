# Hand Gesture Recognition for User-defined Textual Inputs and Gestures

- Accepted on 2024/07/26, published on 2024/08/02 by Wang et al.
- Introduction of an _adaptable GUI_ supporting user-defined hand gestures
  - Training of a camera-based HGR model for a **particular user**
    - User data just from that user.
  - Use of a lightweight MLP Architecture based on contrastive learning.
    - Reduces the size of the data needed and the training timeframes.
      - Previous recognition models required massive training datasets.
  - Results -> Rapid convergence and satisfactory accuracy.
  - Collection and analysis initial feedback on the system in deployment.
- **Hand Gesture**: Use of palm and finger movements to convey thoughts and ideas.
  - Allow computer interaction with simple hand movements.
    - Reduce or eliminate the need for additional input devices.
  - Popular in HCI applications.

## Range of Applications of HGR

- Natural User Interface
- Robot Control
- Virtual Gaming
- Virtual Reality
- Communication -> Sign Language Translation

- **Challenge** -> Develop a standardized set of gestures that will be universally used and recognized.
  - Convey to other systems or humans the intended meaning of a user's gesture without having to teach them a new meaning for that gesture.
- **Solution** -> User-defined hand gestures
  - Each user has their own interpreter.

## Previous Studies

- _Jahani et al_ -> They found that in a virtual environment, users preferred to define a hand gesture vocabulary with two hands.
- _Piumsomboon et al._ -> Hand Gestures Guessability in AR
  - Most surface computing prototypes use hand gestures created by system designers, their hand gestures do not always reflect the user's intention.
- _Woobrock et al._ -> Desktop-based hand gesture designing method by eliciting hand gestures from non-technical users.
  - Found that users were particularly concerned about the number of fingers they used.
  - Found that using one hand was more popular than two (_different than in Jahani et al._)

### Problem of Previous Studies

- They analyzed user behavior to improve standardized hand gesture vocabularies.
  - They don't address the problem that the _definition of a hand gesture may vary widely among users from different e.g. cultural backgrounds_.

### New Method Backbone -> Camera HGR

- Combines Image Processing, Pattern Recognition, and AI
- Key Challenge -> Shielding of one hand from the other
  - Leads to poor segmentation, low quality feature vectors
    - Decline in recognition rates.
  - **Difficulty to infer 3D information from 2D data**

- _Ferreira et al._ -> New model based on Contrastive Transformer
  - Showed that learning rich representation from keypoint sequences gives good discrimination between vector embeddings.
  - Use of keypoint sequences generated by Mediapipe tool.

## Paper's Motivation

- Take into account **user's diversity of cultural backgrounds** and **individual signing styles** in the development or use of hand gestures vocabularies.
- Achieve high recognition rates without **multiple cameras** for practical applications.

### Proposition

- UI interface with user-defined hand gesture textual model inputs.
- Operating with a single camera.
- Requires minimal data collection.
- Enable users to develop their own unique expressions.

## Feasibility Research

- _Is it feasible to train a lightweight neural network as an interpreter, using user-defined small datasets for hand gesture words?_

- _Can users with no technical background accept user interface with user-defined hand gestures ?_

## Main Contributions

- A UI with user-defined hand gesture textual inputs
  - Enables the user to define their own hand gestures to their preferences;
- A lightweight parallel MLP neural network based on the contrastive loss function, serving as interpreter of user-defined hand gesture words, and achieving **_fast convergence_** and **high accuracy**.
- A user study (N = 12) based on the analysis of questionnaires to summarize user acceptability.

## Related Work

### Hand Gesture Detection

Real-time detection of dynamics gestures:

- No indication when a hand gesture _start and ends_ in the video.
- Performed hand gesture should be recognized once.
- The entire system should be designed considering **memory** and **computational** power constraints.
- Use of **Mediapipe** for hand gesture detection.

### Hand Gesture Recognition (HGR)

- SOA hand gesture recognition methods still have their limitations.
  - Results in low recognition accuracy
  - Especially with complex hand gestures
  - On very dynamic or particularly long sequences
- _Mittal et al._ -> Modified _LSTM_ model for continuous HGR
  - Recognizes sequences of connected hand gestures.
- _Camgoz et al._ -> Novel _transformer-based_ architecture
  - Jointly learns continous HGR and translations.
  - Trainable in a _end-to-end manner_.
    - Learns a complete task from raw input to final output as one unified system, directly mapping data to decisions without separate steps.
  - Use of large data sets to train complex neural networks.
    - High computational cost of the training phase
      - Affect negatively UX -> Frequently done for dynamic vocabulary.

### UI for User-defined HGR

- Take into account how long it will take to collect the necessary data.
  - Negatively impact user experience.
  - **GESTOP (by _Sky et al._)** -> 15 to 20 minutes to complete data collection for a single hand gestures.
    - Baseline of the paper
- Provide users with input-able ways to develop vocabulary corresponding to their own hand gestures.
  - Assumes that only a **_small number of gestures_** would be defined.
  - Lightweight neural network for recognition trained with contrastive learning.
    - Based on **data augmentation**
      - Reduces time for hand gesture definition by user.

## New Method Architecture

- **User login function**
- **Default mode (mode 0)** -> Allow users to verify hand gesture textual inputs
- **Vocabulary Extension Module** -> Add new words then assign it to a specific gesture within the system.
  - Capture gesture data for 5s -> model training
    - System still interactive during model training.
- **Vocabulary Management Module**
  - Primary purpose is **_not_** to enable users to invent new gestures, but allow them to perform common gestures in their personalized way.
    - Still perform common gestures.
- **Model Analysis Component** -> Analytical data on recognition system and its performance

## Gesture Recognition

### Hand Gesture Data

- **Data acquisition** -> The system record hand gestures for 5s at a frame rate of 18 fps resulting about 90 images for each hand gesture.
- **Data augmentation** -> Rotation of video frames by 180 degrees about the origin (p0) and then scaled down by a factor of 0.8 to reduce image size.
  - Decrease the computational load and compute time.

### MLP Architecture

- Use of two MLP for the contrastive learning model
- Model is re-trained in real-time with user provided data
- The original data is used as input to the first MLP
  - Gesture localization
- The augmented data is used as input to the second MLP

## Experimental Evaluation

- Make the model converge fast to prevent long training times
- User experience matters
- Double MLP model with CL loss can achieve fast convergence and acceptable accuracy rates
  - But where limited vocabularies are used
  - As the number of gestures in the vocabulary rises, the accuracy declines.

### User Study

- Some users found the system **_impractical_**.
- People found it difficult to use ( multi-step approach)
- User information management is too simple.
- Lack of feedback in the system.
- **Only supports static user-defined hand gestures**.

## Limitations

- System based on static gestures only.
- Lack of interactivity of the UI and lack of system security.
- Users found it tedious to add user-defined hand gestures as they had to click multiple buttons.
- Demand for a relatively large amount of user data.
- **Defining more than six gestures and providing training and test data was seen as demanding and challenging**.
- Training conducted on static datasets.
  - Knowledge base of the model remains unchanged post-training.
    - Lack the ability to incorporate new information.
  - Model does not adapt or evolve in response to subsequent data.
- System's inability to function without a camera.
